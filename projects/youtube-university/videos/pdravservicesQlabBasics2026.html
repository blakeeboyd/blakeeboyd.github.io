Takeaway

QLab is the show-control software that fires the video and audio cues behind live events, and this tutorial builds a themed-venue show from an empty workspace. PDR AV Services opens a park-specific template, confirms which physical output each cue feeds using the grid feature, then imports a video cue and sets its geometry, looping, and routing. The middle of the video covers fades, which QLab builds as separate fade cues acting on opacity over a curve duration, plus the three continue modes (do not continue, auto continue, auto follow) that decide how cues chain. It closes with audio import and trimming, level fades, pause and start cues, and hotkey triggers that fire cues from the keyboard.

Questions

  1. 1.The video opens a workspace from a park-specific template and then checks which physical output each video cue feeds, using the grid feature. Explain why an operator confirms output routing before firing any cue, and what the grid does.Understand

    Before firing a cue, the operator confirms each cue is pointing at the right physical output, because a themed venue may have several displays (an LED wall and side screens) plus an audio path, and those assignments can shift between machines or setups. The grid feature places a visible grid on whichever output a cue targets, so the operator can look at the room and match the on-screen grid to the actual display. The template loads a park's known outputs as a starting point, and the grid verifies them.

  2. 2.In QLab, a fade is built as its own separate cue. Summarize how the presenter builds a fade-on for a video cue, including what opacity and the curve duration do, and why the original cue's opacity is set to zero.Understand

    The presenter adds a separate fade cue and points it at the video cue, opens its geometry, and sets opacity to 100% so the fade ramps the image up to full. The curve duration controls how long the fade takes. The original video cue's own opacity is set to 0% so the image starts invisible, and the fade cue brings it up. The red cross on the fade signals that no parameter is set yet, so the fade does nothing until opacity is enabled.

  3. 3.The presenter assigns hotkey triggers so number one pauses a cue and number two starts it. Describe the steps to set a hotkey trigger on a cue, and explain a situation in a live show where firing cues from the keyboard would beat clicking go.Apply

    To set a hotkey trigger, select the cue, go to triggers, choose hotkey trigger, and assign a key, such as number one for pause and number two for start. During a live show the operator often has both hands busy and eyes on the stage, so a dedicated key fires a specific cue instantly without hunting through the list or relying on the single go button, which only advances to the next cue in sequence. Hotkeys help most when a cue is fired often or out of order, like pausing and restarting a track on a performer's signal.

  4. 4.The video uses several organizing tools on the cue list: grouping cues, labeling them, color-coding (red for stops, green for go), and the three continue modes. Analyze how these work together to keep a cue list readable and reliable during a show, and what would go wrong without them.Analyze

    Grouping collapses related cues into one tidy entry, so a long list stays readable when many cues pile up. Labeling and color-coding let the operator recognize each cue by sight, with red marking stops and green marking the go cue, so the next action is visible at a glance under pressure. The continue modes control chaining: do not continue fires only the selected cue, auto continue also fires the next cue, and auto follow advances automatically after a cue finishes. Without these, the operator faces an undifferentiated list and has to trigger every step by hand, which is slow and error-prone when a show is running.
