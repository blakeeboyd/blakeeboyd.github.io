Takeaway

A hands-on Open Sound Meter tutorial that lets you practice EQ workflow without a live system. Curtis sets up a transfer-function measurement with a Fostex speaker, creates a math source with the apply function, and attaches three peak filters that act as if they were a hardware EQ on the signal chain. Curtis applies Pat Brown's progressive-narrowing workflow inside the software: capture raw response, view it at 1-point-per-octave smoothing (very coarse), apply broad filters, then narrow to 1/3-octave smoothing and add more surgical filters. You can also invert the captured trace to use as a visual guide for what filter to apply.

Questions

  1. 1.Curtis emphasizes that the transform mode (LTW, or logarithmic time window) must match between the measurement and the filters attached via the math source. Why does this matter, and what would happen if you set different transform modes for the source and the filters?Understand

    The transform mode controls the FFT window length per octave, which determines how the software analyzes the data at each frequency. If the measurement is computed at one resolution and the filters at another, the math source can't combine them meaningfully because they're describing different things at the same frequency labels. Curtis sets all sources to LTW (logarithmic time window): the measurement, the reference, and each filter. Different settings would produce visually wrong output: the math result would show the wrong combination of speaker + filter and the engineer would draw wrong conclusions.

  2. 2.Walk through how to build the math source in Open Sound Meter: which math function does Curtis use (out of available options), how many filter slots does he configure, and how does the "apply" function combine the captured speaker with the filters into a single visible trace?Apply

    The math function Curtis uses is apply (out of options including add, subtract, etc.). He configures four slots: the first is the captured speaker measurement (the source to modify), and the next three are filters that get applied on top. He creates three peak filters via Cmd-F, configures each (LTW transform mode, peak shape, default 1k/0dB/Q=1), then assigns them to filter slots 2, 3, and 4. The math source then displays the result of the speaker + filter1 + filter2 + filter3 combined. Adjusting any filter's gain, frequency, or Q updates the visible math source trace in real time.

  3. 3.Curtis demonstrates inverting the captured magnitude trace as a visual guide for which filters to apply. Explain what "invert magnitude" produces visually and how it helps you choose filter frequencies, gains, and Q values.Apply

    Inverting the magnitude flips the captured trace around the 0 dB axis: a peak in the speaker becomes a dip in the inverted view, and vice versa. The result is a visual map of "what filter shape would make this speaker flat." If the inverted trace shows a 2.5 dB dip at 170 Hz with a moderate Q, the engineer can read the values directly and dial them into a filter: a -2.5 dB peak filter at 170 Hz with that Q produces the inverse correction. The inverted trace makes the EQ task into a tracing exercise rather than a guessing game.

  4. 4.The video applies Pat Brown's broad-to-narrow workflow inside OSM. Compare the 1-point-per-octave view to the 6-points-per-octave view: what kinds of features become visible at the finer smoothing, and why does Curtis still start broad and resist using narrow Q filters first?Analyze

    At 1 point per octave, the trace shows roughly 10 averaged points across the audible spectrum; the major tonal trends are visible (low-end rise, high-end roll-off) and small bumps are smoothed away. At 6 points per octave, the trace shows roughly 60 points and reveals smaller features like a 2 dB peak at 800 Hz or a specific dip at 4 kHz. Curtis starts broad because most of those small features at higher resolution are noise (reflections, microphone position artifacts) rather than true speaker behavior, and applying narrow filters to noise is the "whack-a-mole" error.
